## Mini-Retro

1. **Did the process work?** Yes. The self-review checklist in `research-prompt.md` (acronym audit, per-sentence labeling, confidence-vs-source-count check) caught most issues before the first automated review, but the automated review still found real violations the self-review missed: an acronym (DORA) used only in a Sources-list description and never expanded in narrative prose, and a domain term (HumanEval) never bound to a definitional source. 2. **What slowed down or went wrong?** Two self-review misses were structural, not careless: (a) acronyms appearing only inside a shared repository-item link title (used identically in Related, Sources, and the §0 cross-reference) are easy to treat as an exempt "quoted external title" by analogy with genuine external paper titles, but the reviewer does not extend that exemption to a repo's own item titles reproduced as internal link text; (b) assigning "high confidence" to a claim felt safe when the claim itself was strongly worded in the source, without separately counting how many *independent* sources backed it.
3. **What single change would prevent this next time?** Before the first review trigger, run two explicit greps that are cheap and were missing from my own self-review pass: (1) `grep -oE "\bDORA\b|\bHumanEval\b|\b[A-Z]{2,}\b"` restricted to Related/Sources link *titles* specifically (not just Sources bibliographic descriptions) to catch acronyms embedded in internal repo-item titles, since those are not exempt the way external paper titles are; (2) for every Key Finding assigned "high confidence", count distinct *organisations* behind its cited sources, not just distinct URLs, since a paper and a blog post summarising that same paper count as one source, not two.
4. **Is this a pattern?** Yes, on both counts. The "acronym embedded in an internal repo-item title, treated as exempt like an external paper title" failure is a new sub-variant of the existing "acronym expanded only inside a code block or metadata fence" pattern already in `.github/copilot-instructions.md`'s Known Recurring Failure Patterns table -- the common root is treating anything that looks like a fixed proper-noun string as blanket-exempt from expansion, when only genuine external, verbatim-quoted titles are exempt. The "high confidence with a derivative source counted as independent" failure matches the existing "same organisation or project" pattern in the table, but sharpens it: a blog post that summarises a paper is not independent of that paper even when hosted by a different organisation (JetBrains summarising Lindenbauer et al.'s arXiv work), which the existing table entry does not make explicit.

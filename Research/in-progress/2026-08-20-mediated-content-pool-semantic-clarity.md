# Semantic clarity and conflict resolvability in mediated content pools

## Research Question

What domain-independent methods from knowledge engineering, ontology alignment, inconsistency management, and structured knowledge curation can be applied at the level of a mediated content pool to improve semantic clarity, make latent conflicts easier to surface, and attach explicit resolvability structures that remain useful across downstream execution environments?

## Scope

**In scope:**
- Content-pool-level methods such as semantic normalisation, ontology alignment, conflict detection, invariant extraction, provenance capture, and resolvability annotation
- Mediation mechanisms that shape how pool material is surfaced, indexed, linked, or normalised before any active harness consumes it
- Evaluation criteria for whether pool-level improvements deliver durable leverage across repeated downstream uses
- Comparisons between structural curation patterns that change the pool directly and overlay patterns that preserve raw material while improving clarity and conflict visibility

**Out of scope:**
- Domain-specific rules about what material may or may not be written into the pool
- Techniques that act only inside a transient working context or execution harness
- Policies for how downstream actors should respond once a surfaced conflict is detected

**Constraints:** Treat the content pool as both the accessible material and the mediation layer that exposes it. Prioritise transferable methods with evidence from knowledge graph, ontology, archival, or curated-corpus settings, and distinguish intrinsic pool improvements from benefits that depend on a particular consumer environment.

## Context

This item informs how to make a reusable mediated corpus intrinsically clearer, easier to audit, and more explicitly resolvable before any specific harness or execution environment consumes it.

2. Catalogue concrete pool-level techniques from ontology alignment, truth maintenance, semantic normalisation, provenance, and curation research.
3. Compare how those techniques expose contradictions, preserve context, and support later resolution without relying on a specific execution harness.

5. Synthesize a transferable method set and decision framework for improving pool quality independent of any one application domain.

### §2 Investigation

**A. Semantic normalisation and entity resolution**

[fact] Record linkage and entity resolution identify and merge records or entities that refer to the same real-world object across heterogeneous or duplicated sources, and are foundational preprocessing steps before any conflict-detection step can run over a pool, because undetected duplicates masquerade as independent, non-conflicting facts rather than as the same fact stated twice ([Christen (2012) Data Matching](https://link.springer.com/book/10.1007/978-3-642-31164-2); [Awesome-Entity-Resolution curated bibliography](https://github.com/OlivierBinette/Awesome-Entity-Resolution)). [inference] Standard practice normalises fields before comparison (case-folding, punctuation removal, canonical synonym mapping) and then applies deterministic, probabilistic, or embedding-based matching, because normalisation collapses superficial lexical variance so that the matching step can focus on genuine identity questions rather than formatting noise ([Christen (2012) Data Matching](https://link.springer.com/book/10.1007/978-3-642-31164-2)). [fact] This repository's own prior item established that, for a file-based corpus in the 300 to 400 item range, Levenshtein edit distance of 2 or less combined with token Jaccard similarity of 0.6 or higher is a concrete, dependency-free threshold pair for near-duplicate theme-label detection, and that a controlled vocabulary using the Simple Knowledge Organization System (SKOS) `prefLabel`/`altLabel` pattern keeps a growing pool's terminology from fragmenting into near-synonymous singleton labels ([Similarity algorithms and controlled vocabulary](https://davidamitchell.github.io/Research/research/2026-05-23-similarity-algorithms-controlled-vocabulary.html)). [inference] This is a specific, corpus-scale instance of the general semantic-normalisation method class rather than a special case, because the same edit-distance-plus-token-overlap pattern recurs across entity-resolution tooling built for far larger corpora ([dedupe.dev entity resolution guide](https://dedupe.dev/guides/entity-resolution)).

**B. Ontology alignment as a pool-level conflict-detection method**

[fact] LogMap is a scalable ontology matching tool that integrates description-logic reasoning directly into the alignment process, performing "on the fly" unsatisfiability detection so that a proposed mapping between two ontologies is checked for logical consistency before it is accepted, and it produces automatic repair suggestions when a mapping would introduce an unsatisfiable class ([Jiménez-Ruiz and Cuenca Grau, LogMap Ontology Matching Tool](https://www.cs.ox.ac.uk/isg/tools/LogMap/)). [inference] This demonstrates that conflict detection can be built into the alignment step itself, at the pool-construction stage, rather than deferred to a downstream consumer that discovers the contradiction only when querying the merged ontology, because LogMap's repair step operates on the merged ontology's own axioms independent of any particular query workload ([Jiménez-Ruiz and Cuenca Grau, LogMap Ontology Matching Tool](https://www.cs.ox.ac.uk/isg/tools/LogMap/)). [fact] The Ontology Alignment Evaluation Initiative (OAEI) has run an annual, standardised benchmark campaign since 2004 that compares ontology matching systems across a fixed set of tracks (anatomy, biomedical, conference, multifarm, and others), reporting precision, recall, and F1 score per system per track ([Results of the Ontology Alignment Evaluation Initiative 2025](https://ceur-ws.org/Vol-4144/om2025-oaei-paper0.pdf)). [inference] The existence of a stable, cross-year benchmark shows that alignment quality can be measured independently of any one consuming application, which directly answers this item's evaluation-criteria sub-question (4.2) for the ontology-alignment method class ([Results of the Ontology Alignment Evaluation Initiative 2025](https://ceur-ws.org/Vol-4144/om2025-oaei-paper0.pdf)).

**C. Formal inconsistency management: justifications, minimal repairs, and constraint validation**

[fact] Schlobach and Cornet's non-standard reasoning services for debugging Description Logic (DL) terminologies introduced the pinpointing technique: given an inconsistent or unsatisfiable ontology, the algorithm computes a Minimal Axiom set (MinA), the smallest subset of axioms whose joint presence causes the contradiction, rather than merely reporting that a contradiction exists ([Schlobach and Cornet (2003) Non-Standard Reasoning Services for the Debugging of Description Logic Terminologies](https://www.ijcai.org/Proceedings/03/Papers/053.pdf)). [inference] This is the formal ancestor of "explicit resolvability" as this item's Research Question defines it: a MinA is exactly a resolvability structure, because it tells a later resolver the minimal set of axioms to inspect rather than leaving them to search the entire pool for the cause of a flagged conflict ([Schlobach and Cornet (2003) Non-Standard Reasoning Services for the Debugging of Description Logic Terminologies](https://www.ijcai.org/Proceedings/03/Papers/053.pdf)). [fact] A follow-on journal treatment extended pinpointing to full incoherence debugging across general (not only unfoldable) terminologies and introduced hitting-set-based minimal repair, where a repair removes at least one axiom from every computed justification and a minimal repair does so while removing as few axioms as possible ([Schlobach, Huang, Cornet, and van Harmelen (2007) Debugging Incoherent Terminologies](https://link.springer.com/article/10.1007/s10817-007-9076-z)). [inference] Because a single axiom can participate in multiple justifications, minimal-hitting-set computation is the general mechanism that connects conflict detection to conflict resolution without requiring domain-specific rules about which axiom to prefer, satisfying this item's requirement that pool-level techniques stay domain-independent ([Schlobach, Huang, Cornet, and van Harmelen (2007) Debugging Incoherent Terminologies](https://link.springer.com/article/10.1007/s10817-007-9076-z)). [fact] Shapes Constraint Language (SHACL) is a World Wide Web Consortium (W3C) Recommendation, published in 2017, for validating Resource Description Framework (RDF) graphs against structural and semantic constraints called shapes, covering cardinality, datatype, and pattern restrictions, and it complements RDF Schema (RDFS) and Web Ontology Language (OWL), which support inference rather than validation ([W3C SHACL Recommendation](https://www.w3.org/TR/shacl/)). [inference] SHACL shapes give a pool a machine-checkable, declarative statement of what "semantic clarity" requires structurally (required fields, allowed value ranges, cardinality bounds), which converts an implicit clarity expectation into an explicit, automatically enforceable constraint set, but SHACL alone does not detect semantic contradictions between two otherwise well-formed statements the way DL justification-finding does, so the two methods are complementary rather than substitutable ([W3C SHACL Recommendation](https://www.w3.org/TR/shacl/); [Schlobach and Cornet (2003) Non-Standard Reasoning Services for the Debugging of Description Logic Terminologies](https://www.ijcai.org/Proceedings/03/Papers/053.pdf)).

**D. Belief revision as the theory of resolvability**

[fact] The Alchourrón, Gärdenfors, and Makinson (1985) framework, known as the AGM postulates, formally defines rational belief change through three operations: expansion (adding a new belief), contraction (removing a belief while giving up as little else as possible), and revision (incorporating a new, possibly conflicting belief while restoring consistency with minimal change) ([Alchourrón, Gärdenfors, and Makinson (1985) On the Logic of Theory Change: Partial Meet Contraction and Revision Functions, Journal of Symbolic Logic 50(2)](https://www.cs.huji.ac.il/~lehmann/nonmon/AGM_JSL.pdf)). [inference] The AGM minimal-change principle gives a formal criterion for what "explicit resolvability" should optimise for once a conflict is surfaced at the pool level: a resolution structure is well-formed if it identifies the smallest set of prior commitments that must be revised to accommodate the new, conflicting material, rather than an arbitrary larger set, because minimal change is the property AGM revision is defined to satisfy ([Alchourrón, Gärdenfors, and Makinson (1985) On the Logic of Theory Change, Journal of Symbolic Logic 50(2)](https://www.cs.huji.ac.il/~lehmann/nonmon/AGM_JSL.pdf)). [fact] This repository's prior item on autonomous knowledge curation found that classical Justification-based TMS (JTMS) and Assumption-based TMS (ATMS) implement dependency-directed backtracking so that a single retraction propagates only to the beliefs that depended on it, and that this class of mechanism has not been fully displaced by neural or LLM-based approaches, which still struggle to satisfy AGM rationality postulates under iterated revision ([Autonomous knowledge curation and truth maintenance for agentic ontologies](https://davidamitchell.github.io/Research/research/2026-07-20-autonomous-knowledge-curation-truth-maintenance.html)). [inference] This item treats belief revision and TMS as the theoretical layer underneath the concrete DL justification and repair techniques in §2.C: a MinA is the practical, computable object that an AGM-style contraction operator would need in order to perform minimal-change retraction over a real ontology, connecting the abstract "minimal change" criterion to an implementable mechanism ([Alchourrón, Gärdenfors, and Makinson (1985) On the Logic of Theory Change, Journal of Symbolic Logic 50(2)](https://www.cs.huji.ac.il/~lehmann/nonmon/AGM_JSL.pdf); [Schlobach, Huang, Cornet, and van Harmelen (2007) Debugging Incoherent Terminologies](https://link.springer.com/article/10.1007/s10817-007-9076-z)).

**E. Provenance and resolvability annotation**

[fact] PROV-O is the W3C Provenance Ontology, a standard for representing provenance as relationships among Entity, Activity, and Agent classes in RDF, with core properties `wasGeneratedBy`, `wasDerivedFrom`, `wasAttributedTo`, and `used` that together form a traceable derivation chain from a current fact back to its source material and the process that produced it ([W3C PROV-O: The PROV Ontology](https://www.w3.org/TR/prov-o/)). [inference] A pool that attaches PROV-O provenance to every stored fact has, by construction, an explicit resolvability structure for at least one conflict-resolution strategy (provenance-weighted selection, preferring the fact with the more authoritative or more recent source), because the derivation chain is queryable independently of any consuming application ([W3C PROV-O: The PROV Ontology](https://www.w3.org/TR/prov-o/)). [fact] RDF-star, now incorporated into the RDF 1.2 Candidate Recommendation, allows a triple itself to be treated as a subject or object of another triple (a "triple term"), so that a statement such as a fact's confidence, source, or conflict status can be attached directly to that statement rather than requiring four extra triples per annotation under classical RDF reification ([W3C RDF 1.2 Concepts and Abstract Data Model](https://www.w3.org/TR/rdf12-concepts/)). [inference] Statement-level annotation is a pool-level mechanism specifically because it survives the RDF serialization itself: any downstream harness that queries the pool inherits the annotation without needing its own tracking layer, which is the property this item's scope requires when distinguishing pool-intrinsic techniques from harness-dependent ones ([W3C RDF 1.2 Concepts and Abstract Data Model](https://www.w3.org/TR/rdf12-concepts/)). [fact] This repository's prior item on cross-session provenance schema found that an entity-relation model recording explicit `derived_from` and `superseded_by` edges, rather than relying on retrieval-time inference of relationships, is what allows a research agent to reconstruct why a concept exists and what it replaced across sessions ([Knowledge graph schema for cross-session research provenance](https://davidamitchell.github.io/Research/research/2026-05-02-knowledge-graph-schema-cross-session-research-mcp.html)). [inference] This item generalises that finding: `superseded_by` and `derived_from` edges are a specific application of PROV-O's `wasDerivedFrom` relationship, so a mediated content pool that adopts PROV-O-compatible edges gains both the general provenance benefit documented in the W3C standard and the concrete cross-session reconstruction benefit already validated for this repository's own memory schema ([W3C PROV-O: The PROV Ontology](https://www.w3.org/TR/prov-o/); [Knowledge graph schema for cross-session research provenance](https://davidamitchell.github.io/Research/research/2026-05-02-knowledge-graph-schema-cross-session-research-mcp.html)).

**F. Archival curation as a pool-level, consumer-independent precedent**

[fact] The General International Standard Archival Description, second edition, known as ISAD(G), is a standard maintained by the International Council on Archives (ICA) that requires archival description to preserve provenance (name of the creating body) and original order (the arrangement the records had under their creator), organised as a multi-level description from the whole collection (fonds) down to the individual item ([ICA ISAD(G), second edition](https://www.ica.org/en/isadg-general-international-standard-archival-description-second-edition)). [inference] Archival appraisal and description are performed once, by the archive, independent of which future researcher will later consult the material, which makes ISAD(G) a decades-old, non-computational precedent for the same design goal this item investigates: durable, consumer-independent clarity and traceability attached to a content pool rather than reconstructed by each new reader ([ICA ISAD(G), second edition](https://www.ica.org/en/isadg-general-international-standard-archival-description-second-edition)). [assumption] This item assumes the archival original-order and provenance principles transfer to a digital mediated content pool without material loss of applicability, on the grounds that both settings share the same structural problem (heterogeneous material accumulated over time from multiple originating contexts that must remain individually traceable), though no cited source directly tests this transfer for an AI-consumed content pool specifically ([ICA ISAD(G), second edition](https://www.ica.org/en/isadg-general-international-standard-archival-description-second-edition)).

### §3 Reasoning

[fact] Six pool-level method classes recur across the evidence: semantic normalisation and entity resolution (§2.A), ontology alignment with built-in reasoning (§2.B), formal inconsistency management via justifications and minimal repair (§2.C), belief revision theory (§2.D), provenance and statement-level annotation (§2.E), and archival appraisal and description (§2.F) ([Christen (2012) Data Matching](https://link.springer.com/book/10.1007/978-3-642-31164-2); [Jiménez-Ruiz and Cuenca Grau, LogMap Ontology Matching Tool](https://www.cs.ox.ac.uk/isg/tools/LogMap/); [Schlobach, Huang, Cornet, and van Harmelen (2007) Debugging Incoherent Terminologies](https://link.springer.com/article/10.1007/s10817-007-9076-z); [Alchourrón, Gärdenfors, and Makinson (1985) On the Logic of Theory Change, Journal of Symbolic Logic 50(2)](https://www.cs.huji.ac.il/~lehmann/nonmon/AGM_JSL.pdf); [W3C PROV-O: The PROV Ontology](https://www.w3.org/TR/prov-o/); [ICA ISAD(G), second edition](https://www.ica.org/en/isadg-general-international-standard-archival-description-second-edition)). [inference] These classes divide into two functional layers: detection methods that surface a latent conflict (normalisation reveals duplicates; alignment and DL justification reveal logical contradictions; SHACL reveals structural violations) and resolvability methods that attach durable metadata so a detected conflict can later be resolved without re-deriving its cause (MinA, provenance chains, statement-level annotation, archival description) ([Schlobach, Huang, Cornet, and van Harmelen (2007) Debugging Incoherent Terminologies](https://link.springer.com/article/10.1007/s10817-007-9076-z); [W3C PROV-O: The PROV Ontology](https://www.w3.org/TR/prov-o/)). [inference] Detection without resolvability metadata produces a pool that flags problems repeatedly without becoming easier to fix over time; resolvability metadata without detection produces a well-annotated pool that never surfaces the contradictions the annotations were meant to help resolve, so the two layers must be paired rather than treated as alternatives ([Schlobach, Huang, Cornet, and van Harmelen (2007) Debugging Incoherent Terminologies](https://link.springer.com/article/10.1007/s10817-007-9076-z)). [fact] Every technique identified operates on the pool's stored structure (axioms, triples, records, descriptive metadata) rather than on a specific consumer's working memory, retrieval ranking, or execution state, which is the property this item's scope requires to count as pool-level rather than harness-level ([W3C SHACL Recommendation](https://www.w3.org/TR/shacl/); [W3C RDF 1.2 Concepts and Abstract Data Model](https://www.w3.org/TR/rdf12-concepts/)).

### §5 Depth and Breadth Expansion

**Technical lens.** [inference] The detection-then-resolvability pairing identified in §3 maps directly onto the two halves of the Detect-Then-Resolve pattern already documented for Large Language Model (LLM)-based knowledge graph enrichment in this repository's prior truth-maintenance item, which separated explicit conflict detection from downstream resolution rather than conflating them in a single step ([Autonomous knowledge curation and truth maintenance for agentic ontologies](https://davidamitchell.github.io/Research/research/2026-07-20-autonomous-knowledge-curation-truth-maintenance.html)). [inference] The recurrence of the same detect-then-resolve separation in both the symbolic Description Logic (DL) debugging literature and the neural-symbolic Large Language Model (LLM)-Knowledge Graph (KG) enrichment pipeline documented in that prior item indicates the separation is a structural property of the conflict-resolution problem itself, not an artefact specific to either implementation ([Autonomous knowledge curation and truth maintenance for agentic ontologies](https://davidamitchell.github.io/Research/research/2026-07-20-autonomous-knowledge-curation-truth-maintenance.html); [Schlobach, Huang, Cornet, and van Harmelen (2007) Debugging Incoherent Terminologies](https://link.springer.com/article/10.1007/s10817-007-9076-z)).

**Economic and organisational lens.** [inference] Attaching provenance and justification metadata at write time is more expensive per write than writing raw, unannotated material, but the archival precedent in §2.F shows this cost has historically been accepted because the alternative, re-deriving provenance and context at each future read, multiplies the cost across every downstream consumer rather than paying it once ([ICA ISAD(G), second edition](https://www.ica.org/en/isadg-general-international-standard-archival-description-second-edition)). [assumption] This item assumes the same write-once, read-many cost trade-off holds for an AI-mediated content pool, on the grounds that a pool consulted across many independent agent sessions faces the same amortisation structure as an archive consulted by many independent researchers, though no cited source measures this trade-off quantitatively for an AI-consumed pool ([ICA ISAD(G), second edition](https://www.ica.org/en/isadg-general-international-standard-archival-description-second-edition)).

**Regulatory and governance lens.** [inference] The evaluation-criteria question (§1.4) intersects with this repository's prior item on knowledge curation governance, which required a lifecycle with intake, validation, publication, and retirement stages and logged, versioned change records as the auditability requirement for regulated settings; explicit resolvability metadata (justifications, provenance chains) is what makes such a lifecycle auditable rather than only loggable, because an auditor can trace why a specific fact was retracted rather than only when it changed ([Knowledge curation governance for regulated Artificial Intelligence (AI)](https://davidamitchell.github.io/Research/research/2026-04-22-knowledge-curation-governance-for-regulated-ai.html)).

**Historical lens.** [fact] Formal justification-based conflict resolution predates modern knowledge graphs by decades: this repository's prior truth-maintenance item established that Doyle's 1979 Justification-based Truth Maintenance System (JTMS) paper and de Kleer's 1986 Assumption-based Truth Maintenance System (ATMS) paper both establish dependency tracking as the mechanism for retracting exactly the beliefs that depended on a retracted assumption ([Autonomous knowledge curation and truth maintenance for agentic ontologies](https://davidamitchell.github.io/Research/research/2026-07-20-autonomous-knowledge-curation-truth-maintenance.html)). [fact] The Alchourrón-Gärdenfors-Makinson (AGM) postulates formalising rational belief change were published in 1985, predating both the Semantic Web and today's Large Language Model (LLM)-based agents by roughly two decades ([Alchourrón, Gärdenfors, and Makinson (1985) On the Logic of Theory Change, Journal of Symbolic Logic 50(2)](https://www.cs.huji.ac.il/~lehmann/nonmon/AGM_JSL.pdf)). [inference] This indicates the domain-independent methods this item's Research Question asks for already existed as mature theory well before any current mediated-content-pool implementation, so the practical gap is one of application and tooling integration rather than one of missing foundational theory ([Alchourrón, Gärdenfors, and Makinson (1985) On the Logic of Theory Change, Journal of Symbolic Logic 50(2)](https://www.cs.huji.ac.il/~lehmann/nonmon/AGM_JSL.pdf); [Autonomous knowledge curation and truth maintenance for agentic ontologies](https://davidamitchell.github.io/Research/research/2026-07-20-autonomous-knowledge-curation-truth-maintenance.html)).

**Behavioural lens.** [assumption] This item assumes a human or agent curator reviewing a flagged conflict makes better and faster resolution decisions when presented with a minimal justification (a MinA-style axiom set) than when presented with the full contradictory pool, on the grounds that minimality reduces the search space the curator must inspect, though the cited Description Logic (DL) debugging literature demonstrates minimality as a computational property rather than measuring curator decision speed or accuracy directly ([Schlobach, Huang, Cornet, and van Harmelen (2007) Debugging Incoherent Terminologies](https://link.springer.com/article/10.1007/s10817-007-9076-z)).

### §6 Synthesis

**Executive summary:**

A mediated content pool gains durable, harness-independent semantic clarity and resolvability by pairing conflict-detection methods (semantic normalisation, ontology alignment with built-in reasoning, Description Logic (DL) justification-finding, and Shapes Constraint Language (SHACL) structural validation) with resolvability-annotation methods (provenance chains, statement-level RDF-star annotation, and minimal-axiom-set justifications) rather than adopting either layer alone. [inference; source: https://www.cs.ox.ac.uk/isg/tools/LogMap/; https://www.w3.org/TR/prov-o/] The strongest, most transferable single mechanism identified is the Minimal Axiom set (MinA), because it simultaneously detects a conflict's minimal cause and produces the exact resolvability structure a later resolver needs, requiring no domain-specific rules to compute. [inference; source: https://www.ijcai.org/Proceedings/03/Papers/053.pdf; https://link.springer.com/article/10.1007/s10817-007-9076-z] Durable cross-use leverage is demonstrably achievable and independently measurable, evidenced by the two-decade-old Ontology Alignment Evaluation Initiative (OAEI) benchmark campaign for alignment quality, but no cited evidence measures the equivalent property for an agent-consumed, non-ontological mediated content pool specifically, leaving pool-scale evaluation as the item's principal open gap. [inference; source: https://ceur-ws.org/Vol-4144/om2025-oaei-paper0.pdf]

**Key findings:**

1. **Analysis:**

The evidence separates into two complementary functional layers rather than one continuous method class: detection methods that surface a latent conflict and resolvability methods that attach durable metadata for later resolution. [inference; source: https://link.springer.com/article/10.1007/s10817-007-9076-z] Structural curation, exemplified by LogMap's automatic mapping repair and by AGM-style contraction, changes what the pool asserts; overlay curation, exemplified by PROV-O provenance and RDF-star statement annotation, changes what is knowable about what the pool asserts without altering the underlying assertions. [inference; source: https://www.cs.ox.ac.uk/isg/tools/LogMap/; https://www.w3.org/TR/prov-o/] Overlay curation is the lower-risk default for a pool that must remain usable by multiple, independently evolving downstream harnesses, because it preserves raw material for any consumer that needs it while still making conflicts and their justifications discoverable, whereas structural curation risks silently removing material a different downstream consumer still needed. [inference; source: https://www.cs.ox.ac.uk/isg/tools/LogMap/]

A competing interpretation holds that overlay curation alone is insufficient because an unresolved but well-annotated contradiction still returns to every downstream consumer as an open problem, so pools that can tolerate the risk of premature commitment should prefer structural resolution (LogMap-style repair, AGM-style contraction) at write time rather than deferring resolution indefinitely. [inference; source: https://www.cs.huji.ac.il/~lehmann/nonmon/AGM_JSL.pdf] This item resolves the tension by treating the two as sequential rather than alternative: overlay annotation should run first and by default, since it is reversible and preserves information, while structural resolution should be applied only once a MinA or equivalent minimal-cause structure has been computed and a resolution policy (a Zone 3 or Zone 2 concern under GitHub issue #653, out of scope here) authorises acting on it. [inference; source: https://link.springer.com/article/10.1007/s10817-007-9076-z]

The strongest evaluation-criteria evidence, the OAEI benchmark campaign, applies specifically to ontology alignment and has no directly analogous campaign for provenance-annotation quality or for MinA-style justification quality at pool scale, which weakens this item's confidence that "durable leverage across repeated downstream uses" (the Research Question's evaluation requirement) is measurable for every method class identified rather than only for alignment. [inference; source: https://ceur-ws.org/Vol-4144/om2025-oaei-paper0.pdf]

### Assumptions

Archival original-order and provenance principles are treated as transferable to a digital mediated content pool without material loss of applicability. [assumption; source: https://www.ica.org/en/isadg-general-international-standard-archival-description-second-edition] The justification is that both settings share the same structural problem of heterogeneous material accumulated from multiple originating contexts that must remain individually traceable, though no cited source directly tests this transfer for an AI-consumed content pool. [assumption; source: https://www.ica.org/en/isadg-general-international-standard-archival-description-second-edition]

The write-once, read-many cost trade-off documented for archival description is assumed to also hold for an AI-mediated content pool. [assumption; source: https://www.ica.org/en/isadg-general-international-standard-archival-description-second-edition] A pool consulted across many independent agent sessions is assumed to face the same amortisation structure as an archive consulted by many independent researchers, though no cited source measures this trade-off quantitatively for an AI-consumed pool. [assumption; source: https://www.ica.org/en/isadg-general-international-standard-archival-description-second-edition]

A curator reviewing a flagged conflict is assumed to resolve it faster and more accurately when given a minimal justification rather than the full contradictory pool. [assumption; source: https://link.springer.com/article/10.1007/s10817-007-9076-z] Minimality is assumed to reduce the search space the curator must inspect, though the cited Description Logic (DL) debugging literature demonstrates minimality only as a computational property, not as a measured curator-performance outcome. [assumption; source: https://link.springer.com/article/10.1007/s10817-007-9076-z]

### Analysis

The evidence separates into two complementary functional layers rather than one continuous method class: detection methods that surface a latent conflict and resolvability methods that attach durable metadata for later resolution. [inference; source: https://link.springer.com/article/10.1007/s10817-007-9076-z] Structural curation, exemplified by LogMap's automatic mapping repair and by AGM-style contraction, changes what the pool asserts; overlay curation, exemplified by PROV-O provenance and RDF-star statement annotation, changes what is knowable about what the pool asserts without altering the underlying assertions. [inference; source: https://www.cs.ox.ac.uk/isg/tools/LogMap/; https://www.w3.org/TR/prov-o/] Overlay curation is the lower-risk default for a pool that must remain usable by multiple, independently evolving downstream harnesses, because it preserves raw material for any consumer that needs it while still making conflicts and their justifications discoverable, whereas structural curation risks silently removing material a different downstream consumer still needed. [inference; source: https://www.cs.ox.ac.uk/isg/tools/LogMap/]

A competing interpretation holds that overlay curation alone is insufficient because an unresolved but well-annotated contradiction still returns to every downstream consumer as an open problem, so pools that can tolerate the risk of premature commitment should prefer structural resolution (LogMap-style repair, AGM-style contraction) at write time rather than deferring resolution indefinitely. [inference; source: https://www.cs.huji.ac.il/~lehmann/nonmon/AGM_JSL.pdf] This item resolves the tension by treating the two as sequential rather than alternative: overlay annotation should run first and by default, since it is reversible and preserves information, while structural resolution should be applied only once a MinA or equivalent minimal-cause structure has been computed and a resolution policy (a Zone 3 or Zone 2 concern under GitHub issue #653, out of scope here) authorises acting on it. [inference; source: https://link.springer.com/article/10.1007/s10817-007-9076-z]

The strongest evaluation-criteria evidence, the OAEI benchmark campaign, applies specifically to ontology alignment and has no directly analogous campaign for provenance-annotation quality or for MinA-style justification quality at pool scale, which weakens this item's confidence that "durable leverage across repeated downstream uses" (the Research Question's evaluation requirement) is measurable for every method class identified rather than only for alignment. [inference; source: https://ceur-ws.org/Vol-4144/om2025-oaei-paper0.pdf]

### Risks, Gaps, and Uncertainties

- No cited source evaluates Description Logic (DL) justification-finding or minimal-repair tooling deployed specifically inside an autonomous-agent-consumed mediated content pool; all direct evidence for the MinA mechanism comes from general ontology-engineering debugging studies. [assumption; source: https://link.springer.com/article/10.1007/s10817-007-9076-z] This is treated as the item's largest evidence gap and the first target for any follow-on empirical study. [assumption; source: https://link.springer.com/article/10.1007/s10817-007-9076-z]
- RDF-star and the broader RDF 1.2 specification were at Candidate Recommendation status, not final Recommendation status, at the time this item was researched, so statement-level annotation as a pool-level mechanism rests on a standard still subject to change before ratification. [fact; source: https://www.w3.org/TR/rdf12-concepts/]
- [assumption] The archival-science analogy is not empirically tested for AI-consumed content pools. [assumption; source: https://www.ica.org/en/isadg-general-international-standard-archival-description-second-edition] It is offered as a structural precedent rather than as transferred evidence, and should be validated or falsified by a dedicated future study before being treated as load-bearing. [assumption; source: https://www.ica.org/en/isadg-general-international-standard-archival-description-second-edition]
- [fact] No benchmark equivalent to OAEI exists in the cited evidence for measuring provenance-annotation quality or MinA-style justification quality independent of a consuming application. [fact; source: https://ceur-ws.org/Vol-4144/om2025-oaei-paper0.pdf] This leaves the item unable to fully answer its own evaluation-criteria sub-question for method classes other than ontology alignment. [inference; source: https://ceur-ws.org/Vol-4144/om2025-oaei-paper0.pdf]
- This item did not locate a primary, peer-reviewed source directly measuring curator decision speed or accuracy when given a minimal justification versus a full contradictory pool; the search query "minimal justification curator decision time ontology debugging user study" returned no directly relevant peer-reviewed result, and the corresponding claim is carried as an explicit assumption above.

### Open Questions

- What benchmark methodology would let a mediated content pool's provenance-annotation quality be measured on the same cross-application, cross-year basis that OAEI provides for ontology alignment?
- Does Minimal Axiom set (MinA) computation remain tractable at the scale of a continuously growing, multi-source agent-consumed content pool, or does it require approximation once the pool exceeds the class sizes studied in the classical Description Logic (DL) debugging literature?
- What quantitative evidence would establish or falsify the archival write-once, read-many cost trade-off assumption for an AI-mediated content pool specifically?
